# Bug fixes, validation hardening, and multi-provider TTS unification

A broad housekeeping pass across the Express backend of an audiobook production tool. The change fixes several concrete bugs (transaction return value in chapter split, 404 handler ordering, unused variables, interface mismatch), extracts a duplicated pronunciation-rules function into a shared module, upgrades the timeline's TTS generation to support multiple providers (was ElevenLabs-only), and layers on input validation, rate limiting, and path traversal guards across download endpoints.

**Watch for:** The `err.message` leak in audio error responses exposes internal details unconditionally (confirmed). The path traversal guard in export download relies on `startsWith` which can be bypassed by paths like `/data-evil/...` if DATA_DIR resolves to `/data` (likely). The `generate-and-populate` endpoint bypasses the new rate limiting applied to the generation router since it lives in the timeline router (confirmed).

## High-level view

The chapter split endpoint had a real bug: `res.json()` was called inside the `withTransaction` callback, meaning the response was sent before the transaction committed and the return value was discarded. The fix returns data from the callback and calls `res.json` after the transaction resolves.

The 404 handler for `/api/*` was previously registered after the SPA catch-all, so any request to a non-existent API endpoint would receive `index.html` instead of a JSON error. Moving it above the static serving block fixes this.

The `generateSegmentAudioForTimeline` function in timeline.ts was a hard-coded ElevenLabs-only code path. It now branches on `tts_provider` and delegates to `generateWithProvider` for non-ElevenLabs providers. However, the `generate-and-populate` endpoint that calls this function lives on the timeline router, which does not have the `ttsRateLimit` middleware applied — unlike the generation and segments routers.

Path traversal protection was added to both the render and export download routes using `resolved.startsWith(dataDir)`, which is fragile when `DATA_DIR` doesn't end with a path separator.

Error responses in audio.ts now include `err.message` in a `detail` field with no environment gate, potentially leaking filesystem paths or internal state in production.

## err.message in audio error responses

Every catch block in `audio.ts` now returns `{ error: '...', detail: err.message }`. This detail field has no environment check. Internal errors from `fs.createReadStream`, storage provider failures, or SQL errors will expose file paths and internal state to any caller. The audio routes handle user-facing file operations where the underlying error can be verbose — filesystem paths, permission errors, and SQL constraint messages are all possible values.

## Path traversal guard using startsWith

Both `export.ts` and `render.ts` use this pattern:

```typescript
const resolved = path.resolve(exp.output_path);
const dataDir = path.resolve(DATA_DIR);
if (!resolved.startsWith(dataDir)) { ... }
```

If `DATA_DIR` resolves to `/app/data`, then a path like `/app/data-exfil/secret` passes the check because `"/app/data-exfil/secret".startsWith("/app/data")` is true. The standard fix is to compare against `dataDir + path.sep`.

Exploitation requires the database to contain a malicious `output_path` (the application constructs these paths itself), so the risk is low but the fix is trivial.

## Rate limiting gap on generate-and-populate

The rate limiting topology after this change:

```
/api/chapters/:chapterId/segments  →  ttsRateLimit → segmentsRouter
/api/books/:bookId/generation      →  ttsRateLimit → generationRouter
/api/books/:bookId (timeline)      →  (no rate limit) → timelineRouter
                                         └── POST /generate-and-populate (calls TTS in a loop)
```

The `generate-and-populate` endpoint iterates over every segment in the selected chapters and calls `generateSegmentAudioForTimeline` sequentially. A single request can trigger hundreds of TTS API calls with no rate gate. This is the most expensive endpoint in the application and the one most in need of the limit.

## Duration estimate fallback divergence

The non-ElevenLabs branch in `generateSegmentAudioForTimeline` uses this fallback:

```typescript
durationMs = result.durationMs || Math.round((buffer.length / 24000) * 1000);
```

The constant 24000 bytes/sec corresponds to 192kbps MP3 (ElevenLabs' output format). Deepgram's provider returns 128kbps MP3 and estimates at 16000 bytes/sec. If `result.durationMs` is ever `0` or `undefined`, the fallback produces a ~50% duration overestimate for Deepgram output, leading to incorrect clip positioning on the timeline.
